# Random Data Generator (DHIS2 App)

A DHIS2 application that generates realistic random Tracker and Event data for testing, demos, and development. It uses
program metadata and a flexible configuration to produce Tracked Entity Instances (TEIs), enrollments, and events with
sensible values using @faker-js/faker.


## Features
- Generate TEIs, enrollments, and events for DHIS2 Tracker programs
- Configurable date boundaries for enrollment and event dates
- Support for DHIS2 value types and coordinates, options, booleans, etc.
- Autogenerated attribute values reserved via the DHIS2 API
- Pagination-style generation for large datasets
- Localized faker output (locale aware)

## Requirements

- Node.js 20.x (matches CI)
- pnpm 10.x (this repo declares packageManager: pnpm@10.15.0)
- A DHIS2 instance for development, with a user that can read metadata and reserve autogenerated values

## Getting started

### 1) Install

- Ensure pnpm is installed: npm i -g pnpm@10
- Install dependencies: pnpm install

## Development

### 2) Development server

This is a DHIS2 app. The dev server needs a proxy to your DHIS2 instance.

- Create a .env file in the project root and set the proxy target:
  DHIS2_PROXY=http://localhost:8080/dhis
  Adjust to your DHIS2 base path.

- Start the app:
  pnpm start

This runs d2-app-scripts start and proxies API calls to your DHIS2 instance defined by DHIS2_PROXY.

### 3) Build

- Production build:
  pnpm build

### 4) Deploy to DHIS2

- Create a deployable bundle for your DHIS2 server:
  pnpm deploy

Refer to @dhis2/cli-app-scripts documentation for target configuration and upload.

## Environment and configuration

- d2.config.js describes the DHIS2 app entry, name, and title.
- The app uses @dhis2/app-service-datastore with namespace: hisptz-tracker-data-generator. You may inspect and manage
  stored configurations under this namespace in the DHIS2 Data Store.
- To change locale or program behavior in code-based configs, see src/script and related interfaces in
  src/script/interfaces.

## Script usage (headless)

You can also generate data without the UI using the script entry in src/script/index.ts.

- Run the script with ts-node:
  pnpm run

By default, it instantiates TrackerRandomDataEngine with example config and program metadata and generates a small batch
of TEIs:

- TrackerRandomDataEngine.generate({ count: 10 })

Explore:

- src/script/engine/index.ts for EventRandomDataEngine and TrackerRandomDataEngine
- src/script/constants/dataTypes.ts for supported data types and defaults
- src/script/interfaces for configuration shapes (DataConfiguration, EventProgramDataConfiguration, etc.)

Note: For features that call the DHIS2 API (e.g., autogenerated values), a DataEngine implementation wired to a DHIS2
backend is required. In the UI this is provided via @dhis2/app-runtime; in headless mode you may need to adapt the
engine to point at your instance or mock it.

## Testing

- Run unit tests:
  pnpm test

- Open the Vitest UI with coverage:
  pnpm test-ui

Test setup is configured in vitest.config.ts and tests/setup.ts (jsdom environment, Testing Library, jest-dom matchers).

## Release and versioning

This repository uses Conventional Commits and semantic-release to automate releases from the main branch.

- CI workflow: .github/workflows/release.yml
- Configuration: release.config.js
- On merge to main, semantic-release analyzes commits, updates CHANGELOG.md, bumps version in package.json, and creates
  a GitHub release. NPM publishing is disabled (private project).

To run locally (not typical):
pnpm release

## Project structure

- src/App.tsx: App entry; sets up routing and DHIS2 Data Store provider
- src/script/: Data generation engines, constants, and TypeScript interfaces
- d2.config.js: DHIS2 app configuration (name/title/entry)
- vitest.config.ts: Test runner configuration
